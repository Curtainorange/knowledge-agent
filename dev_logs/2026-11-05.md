- [x] **没接住的诉求要说出来**（commit `563a24e`）
      上一版只解决了「意图判对」，没解决「用户说的第三件事没人应」——路由产物只有一个
      能力名，装不下第二件事，装不下就静默丢掉。改法：模型在分流时顺手把
      「提了但办不到」的诉求写成一句人话带回（`unhandled`，≤2 条 / ≤80 字），
      copilot 插在**用户那句话之后**。真机效果：
      ```
      用户：我想学习人工智能，帮我收集整理相关的材料，制定一个学习计划
      副驾：另外，「从网上帮你收集整理人工智能的学习材料」这件事我暂时做不了。

      ```

      我在路由后就写了）。改为按「本轮第一条新 user 消息之后」插入，并补顺序断言。
      不做「执行完再调一次模型组织语言」：那会把「拆好了 12 周任务」也过一遍模型，
      慢、贵、还可能更啰嗦；模型本来已看过整句，顺手写一句的边际成本几乎为零。

## 待办事项

- [ ] **「从网上获取学习材料」的可行性讨论**（用户 09:03 提出，只做了分析，未动手）：
      技术上可行，但**不建议直接抓正文入库**。三条硬约束：① 出网是白名单制
      （`app/llm/policy.py` 8 个主机，无搜索/抓取）；② 知识来源是封闭枚举
      `manual / book / weread`，加 `web` 要改统计口径与各处判定，更麻烦的是**语义变了**——
      这个库的本意是「你读过的、想过的」，混进爬来的网页后，冲突检测与认知简报会开始
      对着二手内容说话；③ 相关性、时效、版权都要额外兜。
      倾向的方案：**只给资源清单，不动知识库**（书 + 检索关键词，不给未核实的 URL），
      零出网、零版权风险；「抓取入库」若真要做，应做成独立的「材料区」，
      与「我的知识库」分开，不参与冲突检测与诊断。
- [ ] 上面那条能力缺口仍待用户拍板：做清单卡 / 做抓取 / 都不做。
- [ ] **「帮我收集整理相关的材料」这件事没有能力承接**。库是空的时候，能做的只有
      推荐书（`book_recommend`）或引导他先记东西。现在这类诉求会被路由到 l4_plan 后
      **静默丢掉**——用户说的话只兑现了一半。要么在计划卡上明说「材料这块我暂时只能
      给书目」，要么做一个「按主题找材料」的诚实入口。**这属于能力缺口，不是 bug。**
- [ ] 复合句现在会多一次模型调用（几十毫秒 + 一点成本）。若日后 `capability_routing`
      的成本在高频会话里显出来，可考虑「本地先验 + 短 prompt」分档，但要先量。

## 备注

- 这次踩的坑值得单独记：**「规则命中」不等于「意图明确」**。规则只看见它认识的那几个词，
  长句里剩下的内容它看不见，也就不会知道自己漏了——它连「可能漏了」都表达不出来。
  已在 `设计决策与经验.md` 补了一节「本地规则的独占边界」。

  被 `test_suggestion.py` 立刻拦下。这类「指令 + 内容」句式的引导词后面是参数不是第二个诉求，
  必须豁免（`_CONTENT_BEARING`）。**旧测试在这里替我省了一次线上事故。**
