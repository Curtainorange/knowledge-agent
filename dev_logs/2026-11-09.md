## 线上故障结论（11-09 09:45 收口）

**现象**：`http://10.100.128.129/cognition/` → 502；任务 `cognition-copilot` 状态「就绪」，
`netstat` 无 8010 监听，`health=000`；日志最后一条停在 **11-07 08:00**（内容正常，无 Traceback）。

**恢复**：`schtasks /run /tn "cognition-copilot"` → `health=200`，网站恢复。

**排除掉的假设（每个都有证据）**：

| 假设 | 证据 | 结论 |
|---|---|---|
| 任务超时被终止（`ExecutionTimeLimit` 默认 3 天） | `/xml` 里**没有** `ExecutionTimeLimit` 元素 | 否 |
| 11-04 断电导致 | 断电在 11-04 10:04，日志活到 11-07 08:00 | 否，是另一次事故 |
| python 崩溃 | `Application` 日志 EventID 1000 只有 `SearchApp.exe`（Windows 搜索崩在 edgehtml.dll） | 否，噪音 |
| nginx 配置错 | 502 是 nginx 自身产生，`proxy_pass` 指向 `127.0.0.1:8010` 正确 | 否 |

**11-07 08:00 进程死亡的确切原因仍未知**。`findstr` 搜整份 10MB 日志时被 `写入错误` 打断，
证据不可信。**但根因不再是阻塞项**——真正的问题是「死了没人知道」：
任务的触发器只有 `ONSTART`（下次运行时间 `N/A`），进程一死就永久停在「就绪」。

**交付**：`deploy/watchdog.bat`（新建 `cognition-watchdog`，每 5 分钟探 `/health`，
非 200 就 `schtasks /run` 原任务）。**不碰原任务、不碰 nginx、不碰其他项目。**

三个关键设计决策，都是踩过坑才这么写的：

1. **用 `ping -n 13` 做延时，不用 `timeout`** —— 任务以 SYSTEM 身份跑，没有控制台，
   `timeout` 会直接报「输入重定向不受支持」，延时会静默失效、连续探测把服务打死。
2. **重启后仍不通就只记 `STILL DOWN`，绝不 `schtasks /end` 强杀** —— 强杀可能打断
   SQLite 正在进行的写事务，把「服务没起」升级成「数据损坏」。卡死要人来看日志。
3. **install 前两重校验**：同名任务已存在就拒绝（不覆盖别人的），
   被守护的任务命令行里必须含 `E:\projects\renzhifujia` 才继续（不守护别人的任务）。
   这与 `update.bat` 第 29 行的思路一致——**脚本本身必须能拒绝做错事**。

踩坑：`update.bat` 用 `/fo list`（不带 `/v`）去 `find` 任务命令行，但 `list` 输出**不含**
命令行（只有 TaskName / Next Run Time / Status），那条校验形同虚设。
本脚本改用 `/fo list /v`，输出里有 `Task To Run` 才能真匹配。

## 部署脚本二次加固（10:40）

上线前按「先确保这些没问题」逐个验了 watchdog 与 update.bat，挖出四个真问题。

### 1）批处理文件里不能写中文（最险的一个）

把 watchdog.bat 的英文注释换成中文后，直接执行 `deploy\watchdog.bat status` 吐出：

```
'8010' 不是内部或外部命令
'状态是「正在运行」，`find' 不是内部或外部命令
```

原因：cmd.exe 按 OEM 代码页（中文 Windows 是 GBK）逐行解析 .bat，UTF-8 的三字节汉字被
解成乱码字节，把行尾 CR/LF 吞掉，注释片段于是被当成命令执行。**它不会报错说「编码不对」，
只会执行一堆垃圾**——注释里的括号、反引号、路径都能变成命令。

处理：`deploy/*.bat` 全部改回纯 ASCII，中文说明搬进 `README.md`（.md 是 UTF-8，无碍）。
护栏 `test_bat_files_are_pure_ascii` 钉住：任何一个 .bat 出现 >0x7F 字节就报红。

### 2）探活必须 `--noproxy`

实测两行的差别（本机 8010 上没有任何进程监听）：

```
curl.exe -s -o nul -w "%{http_code}" http://127.0.0.1:8010/health   -> 502
curl.exe -s --noproxy "*" ...（同一条地址）                          -> 000
```

502 是代理给的（`HTTP_PROXY=127.0.0.1:65212` 接管了回环地址）。watchdog 若不绕代理，
会认为服务**永远**挂着，每 5 分钟重启一次、永不停歇。`update.bat` 的健康检查同一处坑。

### 3）watchdog 原来兜不住「任务状态卡在 Running」

进程崩了但计划任务状态仍停在「正在运行」时，`schtasks /run` 会被拒绝（任务已在运行），
只做 /run 的 watchdog 永远拉不起来，只会每 5 分钟写一行 STILL DOWN。

改法：先 `/end` 再 `/run`。**不去读状态字样**——中文 Windows 输出是「正在运行」，
`find "Running"` 必然落空；与其做本地化字符串匹配，不如无条件 /end（对没在跑的任务无害）。
同时把「一次探测就动手」改成**连续 3 次失败**才动手（重启窗口、模型冷启动都会短暂 5xx），
重启后等待从 12 秒放宽到 40 秒（冷启动要加载本地 ONNX 模型）。

### 4）update.bat 会与 watchdog 打架，且造成「假成功」

停服到起服之间有几十秒窗口，watchdog 每 5 分钟一拍，正好探到 502 就会用**旧代码**把服务拉起来。
最坏结果不是失败，而是 update.bat 最后探到 200、报「更新成功」，实际跑的是 watchdog 拉起的旧进程。

改法：更新前 `/disable`、结束前 `/enable`，并且**所有失败路径统一走 `:fail` 先恢复 watchdog**
（否则一次失败更新会让守护永久停摆，问题从「服务挂」升级成「服务挂了没人知道」）。
无法暂停 watchdog 时直接中止——宁可这次不更新，也不要一个可能假成功的更新。

### 顺带查清的事实

`Curtainorange/knowledge-agent` 是 **public**（`private:false` / `visibility:public`），
所以服务器**只拉不推不需要任何凭据**，不必配 SSH key 或 token。这条写进 README §9.0，
连同四种首次拉取失败的对照表（网络不通 / 要密码 / dubious ownership / 本地改动冲突）。

watchdog、watchdog 必须 /end 先于 /run、不得用 `find "Running"` 判状态、.bat 必须纯 ASCII。
