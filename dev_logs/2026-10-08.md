### 本次踩坑（三条，都已绕开，值得复用）

1. **PlantUML 无法为"单参与者 + 多用例"生成网格布局**。实测：
   `left to right direction` → 629×3143（极窄长，字缩到 3pt）；
   默认方向 → 4096×553（极宽扁且撞 PlantUML 4096px 上限被裁）。
   根因：所有用例都连到同一个参与者，被强制同 rank，无法二维排布。
   **解法**：改用 matplotlib 手绘用例图（椭圆 + 火柴人 + 边界框），
   输出 1400×1180 / 1400×1260，落到 16cm 宽度后字号约 8pt，清晰可读。
   脚本 `UML/_draw_usecase.py` 可直接复用改数据。

2. **`html-to-docx` 的环境脚本在本机（Windows + Git Bash + 沙箱）跑不通**，三处叠加：
   - 脚本第 86/93 行假设 venv 是 POSIX 布局（`$VENV_DIR/bin/python`），
     Windows 下 `uv venv` 建的是 `Scripts/python.exe` → 每次判定"未就绪"→ 重复 rm+建 → 在 `set -e` 下静默退出（exit 2）；
   - `uv` 是 Windows 原生程序，**只接受 Windows 风格路径**：传 `/c/Users/...` 会被它当成相对路径，
     报 "File not found"（requirements.txt）或 "virtual environment already exists"（venv）；
   - **沙箱会回滚对 `$HOME` 的写入**：脚本打印了 `✓ venv ready`，命令结束后目录依然不存在。
   **解法**：在沙箱外执行 + 全用 `C:/...` 风格路径 + 手动完成三步
   （`uv venv --python 3.12 C:/Users/Curtain/.venv-html-to-docx` →
   `uv pip install --only-binary=:all: -r <requirements>` →
   `Scripts/python.exe -c "import docx,..."`）。装好后脚本即可复用。

3. **`convert(html, output_path=...)` 会丢弃 `base_dir`，导致图片静默不嵌入**。
   `__init__.py` 在传 `output_path` 时会**重建** `ConvertOptions`，只复制 6 个页面参数 + output_path，
   `base_dir` 被丢掉 → `image_resolver` 不生效 → 相对路径图片全部丢失，
   且 **success=true、warnings=[]**（不报错！）。首版成品 76 KB、`word/media` 为空。
   **解法**：把 `output_path` 一并写进 `ConvertOptions`，并且**不传** `output_path` 参数。
   修后 1.27 MB、media 4 张、drawings 4。
   **判据**：docx 体积与图片数是否与源图对得上——遇到"成功但体积异常小"必须先查 media。

### 其它

- 本次走 tencent-docx 的 `full_pipeline`（S1 doc-writer → S2 doc-formatter → S3 doc-converter）：
  溯源记录在 `output/<request_id>/pipeline-state.yaml`，结构化日志在 `output/<request_id>/trace/pipeline.log`。
- 文档转 HTML 用脚本 `UML/_md2typeset_html.py`（md → 规范 HTML：token 注入 / 表格 thead+tbody /
  图片 figure+figcaption / 目录 / 无裸值），比手工写 HTML 更可控、可复现。
- **MCP 读文档的粒度上限**：`doc_resolve_document_structure` 的 `text_preview_length` **上限 200 字符**，
  拿不到整段全文。分工原则——**要"定位"**（拿 idx / paragraph_id / 表格结构）用 MCP，
  `mode=full` + `idx` 即可；**要"迁移内容"**（整篇重排、逐段搬字）则用 python-docx 一次性只读提取，
  比逐段 MCP 查询高效得多。本次即按此分工：MCP 查结构（18 表 / 53 标题 / 0 图），python-docx 提全文。
- **图形脚本里的中文内容串不要用 ASCII 双引号**：`note="…从"知识存储"到…"` 会让 Python 字符串提前结束，
  报 `SyntaxError: invalid syntax`。中文引号/书名号一律用全角「」，且**改成带缩进的替换模式**
  （`    title(ax, ` 而非 `title(ax, `）才能避开函数定义行。
