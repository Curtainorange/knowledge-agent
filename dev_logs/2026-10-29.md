## 备注

两个 bug 都是「接口/状态对了，但用户看到的是错的」这一类（见 `复盘与教训.md` 第 33 条）：
一个是全局名不一致、一个是「返回 None 的语义被调用方误解」。都只能靠端到端断言钉住，
单侧看代码都「对」。

第二批两个 bug 是同一根「确认门禁挡不住模型分流」——一个是门禁条件写窄了（只看 chat 路由，
模型误判成别的能力就漏过），一个是指令判定把内容一起吞了。根因见 `复盘与教训.md` 第 34 条。

**三、`flex: 1` 居中会压缩固定尺寸的图片**

给内容容器加 `flex: 1` + `alignItems/justifyContent: center` 后，Image 会被一起压缩
（设定的 752 宽被压到 640，比例虽保持但整体变小，看着像「图没放对尺寸」）。
修法：给图片外层 Box 加 `flexShrink: 0`。同理，横排卡片高度不同时若用 `alignItems: 'center'`，
每张卡会各自居中、顶部参差，应改 `flex-start`（或给统一 `minHeight`）。

**四、本机没有 LibreOffice / python-pptx，视觉核验只能走 PowerPoint COM**

```powershell
$app = New-Object -ComObject PowerPoint.Application
$pres = $app.Presentations.Open("<pptx绝对路径>", $true, $false, $false)  # 只读、无窗口
$pres.Export("<输出目录>", "PNG", 1280, 720)
$pres.Close(); $app.Quit()
```
导出文件名是 `幻灯片N.PNG`。注意 **PNG 读进来会被缩放显示**（1280×720 显示成 1092×613），
按像素目测「底部空白多少」会算错，要按比例换算回 1280×720 再判断。

**五、多进程同时 `>>` 追加同一日志文件会把行写坏**

今早启动服务时两个后台任务同时追加 `scripts/_srv8000.log`，导致一条中文分隔标记整行消失、
`[Errno 10048]` 那行前半段被吃掉、文件从此被 `grep` 判定为二进制（UTF-8 被从字符中间截断）。
**`grep` 对二进制文件不打印行号也不报错，只静默返回「Binary file matches」—— 看着像「记录不存在」，
其实只是搜不到。** 这种情况用 `awk` 按行号打印绕开判定。

**六、后台任务报 `failed` 有两种，要先分清**

- 撞端口：`exit code 3` + 日志里 `[Errno 10048]`，说明另一个实例已绑定，服务其实是好的。
- 被回收：日志**没有** `Waiting for application shutdown` / `Application shutdown complete`
  这两行（正常退出必有），进程树被整体清理。今日 08:11:42 起的那次跑满 32 分 13 秒被回收，
  `netstat` 随后无监听。
判据仍是三样：`netstat` 的 LISTENING PID、该 PID 的启动时间、`/health` 实际返回。
