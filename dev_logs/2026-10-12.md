## 备注

1. **密钥卫生**：注释里保留真实 Key 是「方便」换「风险」——转录/截图/共享日志
   都可能把它带出去。留空位 + 要用时去控制台重新取，才是正解。
2. 当前生效链：`[DeepSeekProvider]` / `deepseek-flash`（2026-10-02 切换，见当日日志）。
3. **会话删除取硬删而非软删**：需求原话是「删除历史会话（含消息记录）」，消息就存
   在 `conversations.messages` 同一行 JSON 里，硬删一条语义完整；软删要加
   `is_deleted` 列 + 全查询过滤，成本高收益低。软删清单（knowledge/books/users）
   本就不含 conversations。
4. **自动命名集中在 `append_message`**：所有写消息路径（Orchestrator / Copilot /
   L1 / turns）都经过它，写在任何单个调用方都会漏路径。write-once——用户重命名后
   `title` 非空，后续消息不再覆盖（重命名是显式意图，不能被冲掉）。
5. **`kind` 现场派生而不加列**：归类判定只依赖卡片协议（消息 JSON 里现成的
   `card.kind` / `card.capability`），列表请求顺手算，零迁移零回填；将来判定
   口径变了也不用修历史数据。代价是每次列表多扫一遍消息 JSON——单人规模无感。
