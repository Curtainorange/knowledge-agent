- [x] 第三轮（用户反馈「等了很久还是无响应」）：查出**三个叠加问题**，全部修掉。
  1. **question 是硬门槛，按钮点完仍被问「这次想搞清什么」**。用户只点按钮、不打字，
     `missing` 永远剩 `['question']`，所以永远不生成。改成 `_filled("question")`：
     有正在读的书时，书名可代替 question（对应「介绍这本书」这类不额外限定的诉求）。
     `suggestion.build_query` 同步用**短书名**（去掉「（击退拖延症、处理多重任务…）」这类副标题）当 query。
  2. **`_replace_card` 从前往后找、命中即返回**，而 `reading_intake` 卡的 key 恒为 `intake`，
     一场会话里有开场 + 每次追问多张——卡片状态被写到**开场那条消息**上，
     用户正在看的那条一直停在旧状态。改为**从后往前找**（替换最新那条）。前端 `runAction`
     同步改成只替换最后一条匹配（原来 `forEach` 会把所有同 key 的卡都换掉，历史里出现两份建议卡）。
  3. **生成要几秒，界面一动不动**。`runAction` 原来只 `button.disabled = true`，
     现在点下去立刻显示「处理中…」，返回后恢复/替换。
  - 真机验证：账号只有 1 本书、**零条笔记**、不填 question；点完三个按钮直接出
    `suggestion state=ok`，2 条建议，依据是 `book_excerpt`（书里原文）+ `agent_summary`（通读笔记）。
    这正是「介绍这本书从智能体已读的知识库输出」的效果。

- [x] 第四轮：清掉两条遗留待办（阈值实测 + 生成等待感）。
  1. **书籍原文召回阈值实测（用真实书，不是拍脑袋）**。在 `dev.db` 的**副本**上跑
     （全程只读，不碰原库），5 本真书 / 14 组查询，逐条核对命中的前三段。
     实测暴露三个真问题，都不是调个数字能解决的：
     - **书名进打分 = 全书同分**。`build_query` 会把书名拼进 query，原实现又把书名算进
       `title_hit`，于是同一本书的每一块都被抬成同一个分——拿「量子计算的超导比特退相干」
       去问《刻意练习》，194/194 块全部过线。改成：书名既不参与检索、也不参与打分。
     - **书名进检索 = 命中版权页**。BM25 带着书名检索时，头两条是版权页和一段无关对话
       （版权页里书名出现好几次）。改成检索词只用问句（范围本来就限定在本书内）。
     - **「介绍这本书」退化成「取最前面」**。书名型 query 对全书同分，排序取到的
       是版权页 ——《成长的边界》返回的第一条是「未知 成长的边界 [加]大卫·爱泼斯坦 著 范雪竹 译」。
       新增 `is_overview_query()` + `_spread_chunks()`：这类诉求走**全书等距取样**，不走相关性检索。
     - 顺带：点名某本书时**只取那本书**（原来另一本书里「碰巧谈到刻意练习」的段落会以更高分
       挤掉本书自己的内容）；点名的书**没通读过就返回空**，不拿别的书顶替
       （原来问《把时间当作朋友》返回的是《蛤蟆先生》的段落）。
     - 最终阈值（实测分界）：`BOOK_MIN_RELEVANCE=0.14`（无关问句最高 0.133 / 真实命中最低 0.145）、
       `BOOK_RELATIVE_FLOOR=0.55`（滤掉「最强命中之后的擦边段落」）、
       `BOOK_EXCERPT_RELEVANCE_CAP=0.55` 保留（实测会真触发：194 块里 13 块 ≥0.55）。
       版权页判定分强弱两档（强标记命中 1 个即丢，弱标记要 ≥2 个）。
     - **改成全量打分取前几**，不再「先让书内 BM25 选 2 条再打分」：两个打分器口径不同
       （BM25 带 IDF/长度归一，关键词算覆盖率），BM25 选出来的常常不是关键词口径下最相关的，
       实测「通才和专才哪个更好」因此直接变成 0 条。代价是每次扫一本书的块（200 块约 20ms）。
  2. **生成建议改成异步**（`turns._start_inline_suggestion`）：最后一个槽位点完，把确认卡
     **原地**换成 pending 卡（`key` 不变，前端锚点不动），任务入队、worker 跑完 `finish_turn`
     就地改成结果卡，前端 `syncMessages` 自带轮询接上。失败时还原成「按这些给建议」而不是
     原来那道题（用户已经答过了）。没有 worker / 卡片已消失时退回同步。
  - 真机验证（真实模型、真实账号）：最后一个按钮 **0.07s** 返回 pending 卡
    （之前同步等 40s+），后台 **42.7s** 出 `suggestion state=ok`、2 条建议。
  - 测试：新增 `test_is_overview_query`（5 组参数）、`test_overview_query_uses_spread_and_skips_front_matter`、
    `test_title_query_uses_only_the_named_book`、`test_named_but_unread_book_returns_nothing`、
    `test_weak_overlap_filtered_by_relative_floor`、
    `test_last_slot_with_worker_returns_pending_then_worker_writes_result`（含「结果能否写回那条 pending 消息」）。
    全量 pytest 全绿，`harness_check.py` 退出码 0，`node --check` 通过。
