## 备注

**本机新踩的坑：`slidep` 报 `Failed to load native binding`（值得复用）**

- 现象：`slidep upsert-dsl` / `lint` 先正常打印 `converter version`，随后
  `[slidep] fatal: Failed to load native binding`，退出码 1。`slidep --version` 却正常。
- 定位：逐个 `require` 原生模块 → `canvas` / `skia-canvas` / `gl` 全部 OK，只有 `@swc/core` 失败；
  绕开被吞掉的错误直接 `require` 平台包，得到真因：
  `SWC native addon: cannot determine native addon user cache`。
- 根因：**沙箱 bash 环境里 `LOCALAPPDATA` 是空串**（`TEMP` 还指向 `workbuddy-update-x64-workbuddy`）。
  swc 1.16 起用用户缓存目录做原生 addon 的 materialization，取不到就判定失败。
- 解法：调 slidep 前补两个环境变量即可，`LOCALAPPDATA` 是关键，`TEMP/TMP` 只是顺带修：
  `export LOCALAPPDATA="C:\\Users\\Curtain\\AppData\\Local"` +
  `export TEMP="C:\\Users\\Curtain\\AppData\\Local\\Temp"`。
- 已封装成本次用的 `output/_sp.sh`（接受 `NN [page_index]`，内含 PATH + 两个环境变量 + upsert+lint）。
- 与 10-15 记的「shim 失效」不是同一件事：那次是 `node_modules` 布局问题（引擎装到 `lib/node_modules`），
  这次引擎目录 `22.22.2-6/node_modules/@tencent/slidep` 已就位（10-25 重新下载，6.6.2），
  shim 本身可用，坏在原生绑定。
