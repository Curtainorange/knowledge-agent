- 服务不常驻：本机会话结束会被清理，下次需重新启动；改后端代码 / `.env` 后也必须重启进程。
- **同一工作区多会话并行时，一次 commit 会带走整份工作区改动**：本轮 D/B/E 改动没有独立 commit——
  另一个会话提交 `c87d0a1` 时把它们一并带走了（`git status` 因此显示干净，`git log` 里找不到我的提交）。
  启示：开工前先 `git log -1` 核对 HEAD；收工前若 `git status` 干净但自己确实改过文件，
  用 `git show --stat HEAD` 反查改动落在哪个 commit，**不要盲目再提交一次**。
- **重启后要确认「新进程真的绑上端口」**：本次旧实例（PID 10028，改动前的代码）一直占着 8000，
  新进程启动即 `10048` 退出，而 `/health` 仍返回 200——因为响应的是**旧代码**（复盘里「重启了却还是旧行为」的复发）。
  判据：日志出现 `Application startup complete` + `Uvicorn running` 且**没有** `10048`；
  必要时用 `netstat -ano`（**输出是 GBK，需按 gbk 解码**）定位占用进程并 `taskkill /PID <pid> /F`。
