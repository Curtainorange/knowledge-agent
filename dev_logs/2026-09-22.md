  （三个提交：`04c3374` L4 + 基建、`13e3ef0` 微信读书、`871492b` 书架；`pytest` **412 项全绿**）。
  至此**能力目录里 10 项全部已接入对话**，引导卡退化为纯安全网。

  - [x] **L4 拆成三个能力而不是一个 `l4`**。原因很实在：**异步是按能力名判定的**，
    而定目标只写本地库、拆计划调一次模型、偏离检查在 reasoning=on 上跑——速度差一个数量级，
    合成一个能力就没法给它们各自选同步还是异步。
    - `l4_goal`（同步、不调模型）：定目标 + 查看当前目标与计划。两者都是本地操作、
      围绕同一份数据，为一次本地查询单开一个能力不值得。
    - `l4_plan`（异步）：把**最近创建的目标**拆成周计划（不做「问用户是哪个目标」——
      多目标下追问一轮的价值远低于直接作用于最新的那个，而卡上带目标描述，拆错了用户一眼能看出来）。
    - `l4_deviation`（异步）：本地算信号，**确认有偏离才调模型**做归因。
  - [x] **两块新基建**（L4 与后续都要用）：
    - **按钮发消息**（`data-agent-send`）：点它等于替用户说一句话，复用整条异步回合链路。
      与 `data-agent-action` 的分界线是**耗时**——秒级改状态走 actions，要跑模型就发消息。
    - **异步卡片操作**：慢操作（按建议重排计划）先返回 pending 卡并把**原卡存进 `restore`**，
      任务失败时原样还原 + 附失败原因。用户不该因为一次执行失败，把已经拿到的偏离分析也丢掉。
      卡片的 `key` 全程不变，前端锚点才稳定。
  - [x] **新增 `preflight` 前提检查**：没配微信读书 Key、或还没定学习目标时，**同步回提示卡、不排队**。
    异步回合是「先占位、后台跑」，前提检查若放在后台，用户会先看到「正在同步…」、
    等一个轮询周期之后才被告知缺的是一把 Key。
  - [x] **微信读书同步**：结果卡把四个核心数字单独成块（有笔记的书 / 本次扫描 / 新增 / 已存在跳过），

    看起来就像漏了数据。幂等由同步服务保证（`source_item_id` 去重，软删的条目也算已存在），
    「再同步一次」这类按钮才敢给。

## 待办事项

- [ ] **`worker` 侧模型仍不可注入（可测性缺口）**：`handlers.agent_turn` 与既有的 `l2_scan` 一样
  在内部自建 `ModelGateway()`，所以走后台路径的能力在测试里拿不到注入的假 provider。
  当前做法是「异步管道」用 Mock 端到端验证、「卡片内容与操作」直接构造卡片或走同步兜底路径验证。
  要端到端脚本化需给 worker 加 provider 工厂配置项——与 pgvector 一样属于
  「收益要等外部条件具备才体现」的一类，暂缓。
- [ ] **对话入口的多轮指代**：分流只看当前这一句、不含会话历史，所以「再来一次」「那个呢」
  会落到通用对话。要接的话得把最近一两轮作为分流上下文。
- [ ] **L4 的多目标选择**：`l4_plan` 目前固定作用于最新创建的目标。目标多起来之后
  需要一个「选哪个目标」的入口（卡片上的目标切换，或让分流模型把目标名带进 args）。
- [ ] **服务持久化**仍未解决（本机安全策略禁用 `schtasks.exe`），当前只能手动启动或本会话后台跑。
