## 备注

- **「页面一片空」和「数据丢了」长得一模一样，但排查路径完全不同**：
  本次与 09-15 上午那次「数据全部没有了」是**同一个观感、两个原因**（那次是账号不符，
  这次是令牌过期）。遇到这类报障先分三步定性：**①库里的数据还在吗 → ②后端接口还正常吗
  → ③前端有没有真的跑起来**。前两步用只读 SQL + curl 几分钟就能排除，第三步才是大头。
  本次两步就排除了「数据丢」和「后端坏」，把范围精确收缩到前端会话。
- **401 的「不回跳」规则必须用白名单，不能用路径前缀**：用前缀排除等于把
  「会话探针」和「登录接口」混为一谈。判据是**「这个 401 是不是在说『你还没登录』」**——
  login/register/password 的 401 说的是「凭证不对」（要原样报错），
  `/auth/me` 的 401 说的才是「登录已过期」（要跳登录页）。
- **「静默失败」比「报错」危险得多**：这次真正的伤害不是令牌过期（很常见），
  而是过期后**页面既不跳转也不提示**，直接渲染成一个死壳——用户只会得出
  「我的数据没了」这个错误结论。凡「校验失败就 return」的写法，都要问一句：
  **失败态用户看得见吗？关键操作（退出）还能用吗？**
- **存了不用的凭证就是隐藏的技术债**：`refresh_token` 从 P0 阶段就存在 localStorage 里
  （`refresh_token_days=7`），却从来没被读取过。这类「只写不读」的字段平时完全无害，
  一旦 access 过期就暴露出「本来可以无感续期，却只能强制重新登录」。
- **前端逻辑也要能被自动化验证**：本次用 `vm` + stub 浏览器 API 跑真实 `app.js`，
