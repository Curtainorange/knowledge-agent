## 二、每个维度的得分点话术（对着评分细则说）

**实用性（20 分）**
- 关键词：**「不是交作业的 demo，是每天在用的系统」**
- 证据：微信读书官方接口同步、4 本真书完整通读（单本 20.8 万字）、持续入库的行为事件、项目全程 19 篇开发日志
- 加分句：「这个系统先服务了开发者自己，才谈得上智能。」

**创新性（15 分）**——老师明确要求「说清楚和现有方案比，好在哪里」
- 必答句：「判一个系统是不是智能体，我问四个问题：有没有跨会话的持久状态？能不能改变外部世界？会不会主动发起？输出能不能反向改进自己？——豆包和笔记软件在这四个问题上几乎全是『否』，我的系统全是『是』。」
- 三个创新点：选题切「认知过程」而非「内容存储」；L2 冲突检测 + 影子主张跨来源对撞（4 本真书验证过）；向量先筛再让模型判（省钱且可讲清原理）

**技术先进性（20 分）**——**这一维度现在由 P7–P13 六页支撑，是本版最强项**
- 选型理由一句话：「FastAPI 保证类型即契约；前端零框架零构建，现场就能跑；存储先用 SQLite，向量层是抽象 + 两个实现（内存索引 / PostgreSQL pgvector）。」
- AI 深度的王牌实验：「结构化输出三种做法对比——自由文本解析 3 次挂 1 次，`json_object` 5/6 且结构被压平，**服务端 Schema 约束 6 次全过**。结论：约束交给服务端，比事后修补可靠。」
- RAG 王牌句：「本地 BGE 中文向量、512 维、ONNX 离线部署，检索走 PostgreSQL 的 pgvector 库内余弦，双通道召回 + RRF 融合，全程不依赖外部云服务。」
- 难度证据：五级冲突漏斗（距离带 0.35~0.95、每轮 ≤20 对、置信度 <0.5 丢弃、低置信复核）；检索评估护栏 recall@5 ≥ 0.95；L2 判定真实评测 F1 = 1.0

**功能完善性（20 分）**
- ⚠️ **死线条款：演示时系统完全无法运行且无屏幕备份 → 本维度记 0 分**（见第三节预案）
- 逐子项报：完成度 8（10 项能力全接入对话）/ 稳定容错 5（自动回退、降级、静默续期）/ 界面 4（对话即入口）/ 代码质量 3（**660 项测试全绿**）

**开发工作量（10 分）**
- 「只看有效工作量」的对策：**166 次提交粒度真实、22 天有记录、27 天周期、19 篇日志 + 20 条复盘**，全是可核查的过程证据
- ⚠️ **AI 辅助编程条款：「被鼓励，但须能讲清生成代码的原理与修改过程」**——PPT 第 19 页已主动声明，口头补一句：「每一处改动有 **660 项测试**和逐日日志把关，原理我说得清，改动可追溯。」**不要等老师问。**

**现场表现（15 分）**
- 演示路线 5 步（PPT P20）：对话录入 → 模糊找回（L1）→ 冲突检测（L2）→ 认知助产 + 计划修正（L3/L4）→ 归因诊断 + 主动推送（L5）
- 每步一句话介绍即可，让系统自己说话；**PPT 的 P21–P26 六页实录既是真人操作后的对照页，也是录屏备份的载体**

## 三、演示预案（开讲前必须做完）

1. **提前录屏**：把 5 步演示路线完整录一遍（OBS / Win+G 均可），存本地 + 传手机一份
2. **关键界面截图**：对话卡片、冲突检测结果、周简报，各截 2–3 张（**已插入 PPT P21–P26，可直接当备份**）
3. **开讲前试跑一次**：`start_server.bat` 启动 → 浏览器走一遍 5 步 → 确认模型 Key 可用、冲突检测有存量数据
4. **提前 15 分钟到场**：开服务器、登好账号、预加载好数据（冲突检测要有存量数据才能当场出结果）
5. 现场顺序：**先跑真系统；一卡住（超过 20 秒）立刻切录屏**，不要现场调试——评分只看「能不能看到功能」
6. **注意**：开讲前确认服务器进程还活着（请求一次 `/health`）——如果是之前由助手在本会话里临时启动的，可能已经随会话结束被回收；到时用 `start_server.bat` 重新拉起即可。

## 四、高频问答准备（详细版见同目录 `技术问答预测.md`，26 题四梯队）

| 老师可能问 | 30 秒答法 |
|---|---|
| 什么是智能体？和大模型/豆包的区别 | 模型是引擎，智能体是车：记忆 + 工具 + 规划 + 自主。豆包答完就忘，我的系统有持久状态、会主动发起、能改你的计划 |
| RAG 了解多少 | 八环节背一遍：切分→向量化→索引→混合召回→RRF 融合→重排→生成→评估；每环节落到「我做了什么/为什么不做」（重排没做：单用户规模收益小于复杂度，已登记） |
| 为什么用本地向量模型 + pgvector | 向量化不依赖外部云 API（离线可用、可复现）；pgvector 是「库内检索」的标准做法，量上来从内存索引切过去无需改上层逻辑 |
| AI 帮你写了多少代码 | 大方承认深度使用，重点讲把关：660 项测试断言、提示词指纹回归、每轮评测回归承诺；能讲清任何一段代码的原理 |
| 最大的收获/踩坑 | 「静默失败比报错危险」：SQL 写错被降级链吃掉、配置没生效服务照跑——所以建了评估集、自检端点，模拟结果绝不冒充真实结果 |
| 数据量大了怎么办 | 已知瓶颈（向量检索规模、候选对 O(n²)）都登记在案；pgvector 后端已实现且有测试，量上来切过去即可，评估护栏会先告诉我检索质量有没有掉 |
| 模型怎么选型（追问供应商） | 只答方法不答品牌：「按能力位分派——支持 Schema 约束的走约束生成，不支持的在本地做三层兜底；思考模式按任务开关控制成本。」**不要主动提具体供应商链** |
