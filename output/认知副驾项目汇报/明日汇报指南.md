## 二、每个维度的得分点话术（对着评分细则说）

**实用性（20 分）**
- 关键词：**「不是交作业的 demo，是每天在用的系统」**
- 证据：微信读书官方接口同步、4 本真书完整通读（单本 20.8 万字）、589 条行为事件、连续 21 天开发日志
- 加分句：「这个系统先服务了开发者自己，才谈得上智能。」

**创新性（15 分）**——老师明确要求「说清楚和现有方案比，好在哪里」
- 必答句：「判一个系统是不是智能体，我问四个问题：有没有跨会话的持久状态？能不能改变外部世界？会不会主动发起？输出能不能反向改进自己？——豆包和笔记软件在这四个问题上几乎全是『否』，我的系统全是『是』。」
- 三个创新点：选题切「认知过程」而非「内容存储」；L2 冲突检测 + 影子主张跨来源对撞（4 本真书验证过）；向量先筛再让模型判（省钱且可讲清原理）

**技术先进性（20 分）**
- 选型理由一句话：「FastAPI + SQLAlchemy + SQLite 对单人规模是负复杂度选择；检索层本地 BGE 中文向量 + PostgreSQL pgvector 向量库，向量+关键词双通道、RRF 融合，全程不依赖外部云服务。」
- AI 深度的王牌实验：「结构化输出三种做法对比——自由文本解析 3 次挂 1 次，Schema 约束 6 次全过。结论：约束交给服务端比事后修补可靠。」
- 难度证据：检索评估集护栏（recall@5 ≥ 0.95）、L2 判定真实评测 F1 = 1.0

**功能完善性（20 分）**
- ⚠️ **死线条款：演示时系统完全无法运行且无屏幕备份 → 本维度记 0 分**（见下文预案）
- 逐子项报：完成度 8（10 项能力全接入对话）/ 稳定容错 5（自动回退、降级、静默续期）/ 界面 4（对话即入口）/ 代码质量 3（647 测试全绿）

**开发工作量（10 分）**
- 「只看有效工作量」的对策：154 次提交粒度真实、20 天有记录、21 天日志 + 20 条复盘，全是可核查的过程证据
- ⚠️ **AI 辅助编程条款：「被鼓励，但须能讲清生成代码的原理与修改过程」**——PPT 第 12 页已主动声明，口头补一句：「每一处改动有 647 项测试和逐日日志把关，原理我说得清，改动可追溯。」不要等老师问。

**现场表现（15 分）**
- 演示路线 5 步（PPT P13）：对话录入 → 模糊找回 → 冲突检测 → 计划修正 → 主动推送
- 每步一句话介绍即可，让系统自己说话

## 四、高频问答准备（详细版在 docs/周工作汇报-2026-09-23.md）

| 老师可能问 | 30 秒答法 |
|---|---|
| 什么是智能体？和大模型/豆包的区别 | 模型是引擎，智能体是车：记忆 + 工具 + 规划 + 自主。豆包答完就忘，我的系统有持久状态、会主动发起、能改你的计划 |
| RAG 了解多少 | 八环节背一遍：切分→向量化→索引→混合召回→RRF 融合→重排→生成→评估；每环节落到「我做了什么/为什么不做」（重排没做：单用户规模收益小于复杂度） |
| 为什么用本地向量模型 + pgvector | 向量化不依赖外部云 API（离线可用、可复现）；pgvector 是「库内检索」的标准做法，量上来从内存索引切过去无需改上层逻辑 |
| AI 帮你写了多少代码 | 大方承认深度使用，重点讲把关：测试断言、提示词指纹回归、每轮评测回归承诺；能讲清任何一段代码的原理 |
| 最大的收获/踩坑 | 「静默失败比报错危险」：SQL 写错被降级链吃掉、配置没生效服务照跑——所以建了评估集、自检端点，模拟结果绝不冒充真实结果 |
| 数据量大了怎么办 | 已知瓶颈（向量检索规模、候选对 O(n²)）都登记在案；pgvector 后端已实现，量上来切过去即可，评估护栏会先告诉我检索质量有没有掉 |
