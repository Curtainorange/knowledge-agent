# B 模块设计：主动建议逻辑改造

- 范围：用户进入页面 → 主动问候 → 需求确认（≤3 轮）→ 基于已同步内容生成建议 → 效果回访
- 状态：**设计稿，待澄清确认后开工**
- **修订提示**：第 1、6、7 条相关口径已由 `docs/验收自检与修正-2026-10-20.md` 修正（建议可被否定 / 2 轮认知探究 / 外部推荐隔离）。**冲突时以修正文档为准**：`evidence[]` 不存在 `external`，外部内容只进 `references[]` 隔离区。
- 日期：2026-10-20
- 关联：`docs/修改方案-2026-10-20.md` B 模块

## 一、需求复述（6 条）

1. 现在的毛病不是"不主动"，是**主动得太早**：`greeting.build_opening()` 5 个分支全部在用户还没说一句话时就直接推动作（扫冲突 / 拆计划 / 看偏离），把"我猜你需要"当成了"你需要"。
2. 建议不个性化的根因是**输入只有阅读痕迹**：现有信号是 `read_progress`、条目数、学习事件数、未解冲突数。没有阅读目标、没有理解程度、没有这一次的具体疑问，模型只能按"通用读者"给建议。
3. 改造后的顺序是硬约束：**问候 → 确认（≤3 轮）→ 生成建议**。确认没完成不得出建议——这不是提示词要求，是代码门禁。
4. 「确认」不等于「审问」：5 个确认项不能拆成 5 个问题。要靠系统先推断（正在读哪本、读到哪）、把推断结果给用户点确认，只把真正不知道的才问出口。
5. 建议必须**可溯源**：每条建议标注它来自哪些已同步内容（哪本书哪一章的划线 / 你自己记的笔记），点得开、看得到原文。
6. 未入库的内容一律不得作为依据：用户提到一本没同步的书，正确反应是"这本还没进来，我不能拿它当依据"，不是假装读过。

## 二、需要确认的澄清问题（6 条）

| # | 问题 | 为什么必须问 | 我的默认假设 |
|---|---|---|---|
| Q1 | 「最多 3 轮」是硬上限，还是"用户首句已说清就可以 0 轮直接出建议"？ | 决定门禁是"轮数"还是"槽位完整性" | **槽位驱动**：5 项齐了立刻出建议，不管几轮；3 轮是上限不是流程 |
| Q2 | 「理解程度」用自评 3 档（首次接触 / 读过一遍 / 能讲给别人）够不够？要不要强制复述检验？ | 强制复述会让用户打字，交互成本翻倍 | 自评 3 档为主；仅当 `self_level=teach` 或用户主动给了复述时才做判分 |
| Q3 | 「阅读目标」的 5 类枚举（学概念 / 解决具体问题 / 做输出 / 考试 / 兴趣泛读）符合你的业务吗？ | 会固化成枚举，后端与卡片都依赖它 | 按这 5 类，另留 `other` + 自由文本 |
| Q4 | **依据不足时，允许模型用通用知识回答并标注"非你的知识库"吗**？还是严格拒绝、只提示补料？ | 这是产品立场问题，不是技术问题 | **严格模式**：库里无相关内容就不出建议，只说明缺什么（符合"未入库不得作为依据"） |
| Q5 | 用户说"别问了，直接给建议"时，是坚持先确认还是允许跳过？ | 关系到门禁强度与体验 | 允许跳 1 次，但建议卡必须挂"未确认目标，依据相关性可能偏低" |
| Q6 | 建议要不要落表（`suggestions`）供后续回访与效果评估？ | 要多一张表 + 迁移，2 天工期紧张 | 本期落表（回访依赖它），字段精简到 8 列 |

补充一条实现事实，需要你知晓（不是问题，是约束）：**微信读书同步不返回整本书阅读进度**，只落划线的 `chapter_title / chapter_index / marked_at`。所以「当前进度」对微信读书来源只能推断到"最近划到第几章"，显示时必须标"推断"，不能写成百分比。

## 三、交互流程图（文字版）

### 3.0 关键定义

- **一轮 = 用户的一次输入**。助手开场说话不算轮。
- **槽位**：5 个确认项落成结构化字段，齐了才能出建议。缺哪项问哪项，不问已回答的。
- **状态机**：`collecting` →（槽位齐）→ `ready` →（生成完成）→ `suggested`；任一环节放弃 → `abandoned`。

### 3.1 主流程（状态机）

```
[用户进入 app.html]
   │
   ├─ 会话已有 reading_context 且 status=suggested？
   │     └─ 是 → 恢复上次会话，开场说一句"接着上次《X》的问题"，不再重复确认
   │
   ├─ 知识库为空（count_active == 0）？
   │     └─ 是 → 走【空库分支 E3】，不进入确认流程
   │
   ▼
[SS0 主动问候：不占轮]
   助手输出（一条消息，不调模型，模板拼装）：
   "我是你的认知副驾。你最近在读《X》，读到第 3 章（推断）。
    今天想接着读，还是先解决一个具体问题？"
   [+ 若存在未解冲突：附一句"另外还有 2 处冲突没处理，要顺手过一遍吗？"
      —— 定位为「待办提示」，不是建议，不占确认轮]
   [卡片 kind=reading_intake，round=0]
   │
   ├─ 用户点选"接着读" / "解决问题" / 自由输入
   ▼
[SS1 第 1 轮：确认进度 + 采集疑问]
   采集：progress（已由系统推断，用户只需确认或改）
         question（想解决的问题）
   助手："《X》第 3 章，我记下了。这次具体想搞清什么？"
   [卡片 round=1，只问 1 项：question（自由输入 + 3 个从当前章节生成的猜测选项）]
   │
   ▼
[SS2 第 2 轮：采集目标 + 理解程度]
   助手："想搞清'这个概念怎么落地'——那你读这本书主要是为了用起来（目标=解决问题），
        这块内容你目前是第一次接触，还是已经读过一遍？"
         ← 注意：goal 由 question 推断后**给确认**，不空问
   [卡片 round=2，出 2 项：goal（确认/改）+ self_level（3 选 1）]
   │
   ▼
[SS3 第 3 轮：采集帮助类型 + 复述确认]
   助手复述一句："你要解决的是『如何把 X 用在团队管理上』，读过一遍、需要能落地的步骤。"
         + 问"希望我怎么帮你？"
   [卡片 round=3，出 1 项：help_type（5 选 1）]
   │
   ▼
[SS4 生成建议]
   ① 装配证据（grounding）→ ② 生成 → ③ 引用校验 → ④ 出卡
   失败/依据不足 → 走【异常分支】
   │
   ▼
[SS5 效果回访：不占确认轮，异步]
   建议卡底部："用上了吗？" → 用户点"用上了 / 没用 / 还没看"
   → 写 suggestions.used_state，作为下一次建议的权重输入
```

### 3.2 5 项确认在 3 轮里的分配

| 轮 | 采集项 | 提问形态 | 设计理由 |
|---|---|---|---|
| SS0（不占轮） | 进度（book + progress） | **系统推断 + 一键确认** | 内置书有 `read_progress`，微信读书有最新划线章节，能推就不问 |
| SS1 | 想解决的问题 | 自由输入 + 3 个章节相关猜测 | 这是最有信息量的一项，单独给一轮 |
| SS2 | 阅读目标 + 理解程度 | 目标由疑问推断后确认；理解程度 3 选 1 | 两者都影响建议"密度"，合并一轮 |
| SS3 | 希望帮助类型 | 5 选 1（带一句话说明） | 决定响应形式，最后问最自然；同时给复述确认的机会 |

**为什么这样排**：先采集"时效性最强"的（今天要解决什么），再采"稳定属性"（目标、水平），最后采"形式偏好"。反过来问会显得像填表。

### 3.3 可跳轮规则（重要）

用户输入若是复合句（"我在读《原则》第二章，想问极度透明怎么落地，我读过一遍，直接给我步骤"），按以下顺序抽取槽位：
`book → progress → question → goal → self_level → help_type`，抽到几项填几项。

- 5 项齐 → **跳过剩余轮次，直接出建议**（0 轮也可能）
- 缺 1-2 项 → 只问缺的，卡片只出缺的题
- 用户说"直接给建议" → 走跳轮（见 Q5），挂"未确认"标识

## 五、建议生成规则

### 5.1 证据装配（`grounding.build_evidence`）

1. 查询范围**只允许**两处：
   - `knowledge_items`：`user_id = 当前用户` 且 `is_deleted = false`
   - `book_agent_readings`：`status = 'done'` 且书未被删
2. 检索：`question + goal_note` 作为 query 向量 → 与条目 `embedding` 余弦排序；embedding 不可用时降级关键词召回（沿用现有 `retrieval` 模块）。
3. 取前 K（`K = 8`），**相似度阈值 0.55**，低于阈值不入池。
4. `quote` 抽取：从 `raw_content` 里取命中最长片段，≤120 字；抽不出 → 该条不入池（防止"看起来有依据其实对不上"）。
5. 池子为空 → 返回 `insufficient_evidence`，**不调生成模型**。

### 5.2 生成约束（模型侧）

| 规则 | 内容 |
|---|---|
| 条数 | ≤2 条；`help_type=answer_only` 时只出 1 条且不扩展 |
| 必须项 | 每条必须四要素：`action / why / basis_item_ids / how_to_verify`，缺一即整条丢弃 |
| 密度（按 `self_level`） | `first`：≤1 个专业术语，必须有生活类比；`once`：可用术语，必须给反例或边界；`teach`：直接给争议点、失效条件、与相邻概念的差别 |
| 形式（按 `help_type`） | `explain` → 类比 + 定义 + 一个反例；`evidence` → 只摆库里说法，不做评价，标出互相矛盾处；`path` → `steps` ≤4 步，每步一个动作；`critique` → 指出理解缺口，不肯定性夸奖；`answer_only` → 直答，不追问、不扩展 |
| 目标指针（按 `goal`） | `output` 必须给"可交付物雏形"；`exam` 必须标注"考纲可能不覆盖"；`casual` 不排任务、只给阅读线索 |
| 人称 | 不用"你应该/必须"，用"可以试试/如果…则…"——副驾不给命令 |
| 冲突优先 | 若 `question` 命中库里未解冲突（余弦 ≥ 0.6），**第一条建议必须是"先处理这处矛盾"**，并把冲突双方作为证据 |

### 5.3 引用校验（代码侧，硬拦截）

对每条建议：

1. `basis_item_ids` 必须非空，且每个 id 都在本次 `evidence` 池内（`evidence_id` 精确匹配）。
2. 任一 id 不在池内 → **整条丢弃**（不是删 id 保留文案——文案本身就是幻觉）。
3. 丢弃后条数为 0 → 返回 `insufficient_evidence`，附"我找到的依据不足以支撑建议"。
4. 丢弃 1 条（原 2 条剩 1）→ 正常出 1 条，`note` 说明"另一条因依据不足已省略"。
5. 每条 `quote` 必须在对应 `raw_content` 中命中（字符串包含），否则该证据剔除、依赖它的建议一并丢弃。

### 5.4 置信度计算（代码算，不用模型自评）

```
confidence = 0.4 * min(1, len(basis_item_ids)/3)
           + 0.3 * mean(relevance)
           + 0.2 * (1 if 槽位齐全 else 0.3)
           + 0.1 * (1 if 无丢弃 else 0)
```

- `< 0.5` → 建议卡顶部显示"依据偏薄"
- 槽位不齐（`skipped=true`）→ 上限 0.6

## 六、异常情况处理

| # | 场景 | 触发条件 | 系统行为 | 用户看到 |
|---|---|---|---|---|
| E1 | 知识库为空 | `count_active(0)` | 不进确认流程，不发建议 | "库里还是空的。先记一条，或同步微信读书——没有内容我给的任何建议都是猜的" + 两个动作按钮 |
| E2 | 用户提到的书未同步 | 书名不在 `books` / `knowledge_items` 里 | **拒绝作为依据**，不发建议；可帮用户确认书名后引导同步 | "《X》还没进来，我不能拿它当依据。要现在同步吗？" |
| E3 | 用户只读了微信读书、无可推断章节 | 该书无划线 | 进度项标"未知"，改问一句"读到哪了"（可跳） | "这本我没有你的进度记录，大概读到哪了？（可以跳过）" |
| E4 | 证据不足 | 池子为空或全部低于阈值 | 不调生成模型，`state=insufficient_evidence` | "你库里跟这个问题相关的内容我没找到。可以：① 换个问法 ② 先把这段想法记下来 ③ 先去读相关章节" |
| E5 | 生成结果引用幻觉 | `basis_item_ids` 不在池内 | 整条丢弃；全丢 → 降级为 E4 | 同 E4，`note` 说明"有内容因依据不足被省略" |
| E6 | 模型输出无法解析 | JSON 解析失败 | 重试 1 次，仍失败 → `state=degraded` | "这次没生成成功，重试一下？" + 重试按钮（不静默转圈） |
| E7 | 用户一直跳过确认 | 连续 3 次 `skipped` | 停止追问，降级为"只问一个问题"模式（只留 `question`） | 不再出题，直接："那你说想解决什么，我不问了" |
| E8 | 用户说"直接给建议" | 意图命中 `direct_suggest` | 允许跳轮，`skipped=true` | 建议卡挂"未确认目标，相关性可能偏低" |
| E9 | 用户纠正复述 | 命中"不对/不是/我说的是" | 更新对应槽位，`status` 回退到 `collecting`，作废本次未出建议 | "好，改过来：你要解决的是 Y" |
| E10 | 会话中断后再回来 | 已有 `reading_context` 且 `status=collecting` | 从断点继续，不重问已答项 | "接着刚才的，还差一项：你希望我怎么帮你？" |
| E11 | 用户在读书与自述进度冲突 | 系统进度 80%，用户说"刚翻开" | 以用户为准（`progress_source=user_corrected`），不争辩 | 只在卡片上标注"按你说的记" |
| E12 | 并发会话（多标签页） | 同一 `conversation_id` 两个 tab 同时答 | 以 `updated_at` 最新为准，旧卡片标"已被更新" | 旧卡按钮置灰 |
