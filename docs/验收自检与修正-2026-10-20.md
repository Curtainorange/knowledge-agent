## 三、修正后的最终版本

### 修正 1：建议可被否定，且否定会改变后续行为（对应第 1 条）

**新增交互**：`suggestion` 卡每条建议右侧一个「这条不对」按钮（弱化样式，不与"采纳"抢注意力）。

| 规则 | 内容 |
|---|---|
| 记录 | 点击 → `suggestions.used_state = 'rejected'` + 记 `{rejected_help_type, rejected_goal, pattern}` |
| 收敛 | 同 `help_type + goal` 组合的建议，7 天内不再主动出（改由用户主动问才给） |
| 不追问 | **不弹"为什么不对"**。要原因只在用户自己愿意说时听（"这条不对"后助手只回一句"记下了，这条我不再推"） |
| 出建议前 | 先看该组合是否在收敛期；在则改出 1 条并换角度，或直接说"这类建议你之前否过，我换个方向问你" |
| 条数 | 仍 ≤2。**用户否掉 1 条后不补第 3 条**（补位等于不接受否定） |

**验收**：AT-B-17 同一 `help_type+goal` 被拒后 7 天内不再主动出（断言调用 0 次）；AT-B-18 拒绝后回复中不含"为什么"类追问。

### 修正 2：认知缺口硬性 2 轮探究（对应第 6 条，替代原"单轮降级"）

**放弃原降级方案**。改为固定的 2 轮，第 2 轮按第 1 轮答案分支，不再扩充。

| 轮 | 问什么 | 形态 |
|---|---|---|
| 第 1 轮 | ① 这块内容你之前接触过吗（首次 / 读过一遍 / 能讲给别人）② **一道判断题**：给出 3 个说法，选"哪个更接近书里的意思"（正确项 + 2 个常见误解项，由条目内容生成） | 单选，可跳过 |
| 第 2 轮（分支） | 自评"读过/能讲" **且** 判断题答错 → 追问"用一句话说说它是什么"（复述）<br>自评"首次" → **不追问**，改走引导阅读（不判缺陷）<br>判断题答对 → 判"已掌握，仅缺整理"，不出缺陷结论 | 复述为文本框，可跳过 |

**判定矩阵（代码判定，不交模型）**

| 自评 | 判断题 | 复述 | 结论 |
|---|---|---|---|
| 能讲/读过 | 对 | — | 已掌握（不报缺陷，只可能建议"整理成体系"） |
| 能讲/读过 | 错 | 缺关键点 ≥2 | **理解缺口**（可出诊断） |
| 能讲/读过 | 错 | 覆盖良好 | 认知偏差/表述差异（出"换个说法对齐"，不出"你没懂"） |
| 首次接触 | 任意 | — | **不诊断**，走"引导阅读"路径 |
| 跳过 | 跳过 | — | 不出诊断，置信度不上报 |

**为什么只 2 轮**：第 3 轮起信息增益低于打断成本——第 1 轮定"是否有基础"，第 2 轮定"是不是真懂"，再问下去就变成考试。

**验收**：AT-E-06 未完成 2 轮不得出缺陷结论；AT-E-07 判断题答对 → 输出不含"理解缺口"类结论；AT-E-08 自评"首次" → 走引导路径且不写 `cognitive_diagnoses`；AT-E-09 探针结果写入 `comprehension_probes` 且两轮可区分 `round`。

### 修正 3：依据三级口径统一 + 外部推荐隔离（对应第 7 条，取消 B 模块"本期不做"）

**统一为三种依据等级，全系统只有这一套说法**：

| 等级 | `basis` | 是什么 | 能否进 `basis_item_ids` | UI |
|---|---|---|---|---|
| 一 | `library` | 知识库条目（划线/笔记/手动记） | 能，**每条建议至少 1 条** | 「你的笔记」标签 |
| 二 | `agent_summary` | 智能体通读笔记（基于用户上传的书） | 能，但**不能单独构成依据** | 「通读笔记」标签，颜色区分 |
| 三 | `external` | 外部推荐（未入库） | **永不** | 独立分区，固定标题 |

**`agent_summary` 定性（回应第 4 条的边界）**：它不是你同步进来的内容，是基于你上传的书派生的。所以允许引用但要满足两个硬条件——① 必须标 `kind=agent_summary`；② 每条建议至少有 1 条 `library` 级依据，不能全靠通读笔记。

**外部推荐隔离规则**：

| 规则 | 内容 |
|---|---|
| 位置 | 只出现在 `suggestion.references[]`，与 `items[]` 平级，**永不被 `basis_item_ids` 引用** |
| 强标识 | 每项必带 `external=true` + `external_source`（平台名）+ `unverified=true` |
| UI 标题 | 固定文案「延伸参考（非你的知识库，未入库，仅作线索）」 |
| 条数 | ≤3 |
| 生成 | 复用现有 `book_orchestrator.recommend()`，不新增能力 |
| 数据校验 | 测试断言：`references[]` 里任何 id 都不得出现在 `evidence[]` 中 |

**验收**：AT-B-19 `references[]` 项 100% 带 `external=true` 且不在 `evidence[]`；AT-B-20 仅有 `agent_summary` 依据的建议被判 invalid（`insufficient_evidence`）；AT-B-21 UI 上两类依据分组渲染（人工核对 + 结构断言）。

### 修正 4：冲突归因补「背景」字段（对应第 5 条）

`attribution` 从 6 项扩到 **7 项**，明确对应清单的三块要求：

| 清单要求 | 字段 | 说明 |
|---|---|---|
| **背景** | `background_a` / `background_b` | 各自成书的立场与前提：作者身份、时代、学科范式、写作目的。**必填**，不能省略成"无" |
| 适用范围 | `boundary_a` / `boundary_b` | 各自在多大规模、什么条件、什么对象上成立 |
| 应用指导 | `scene_guidance[].follow` | 具体场景下该照哪一方做，含动作而非原则 |
| 归因 | `cause_type` / `premise_a` / `premise_b` | 六类原因 + 双方前提 |
| 可验证 | `probe` | 一条用户自己能验的判据 |

**硬规则**：`background_a/b` 任一为空 → 整条归因判 `degraded`，不落库（宁可不出，不出半截）。

**展示顺序固定为**：为什么冲突（背景 + 原因）→ 什么时候听 A → 什么时候听 B → 你怎么自己验。

**验收**：AT-D-06 `background_a/b` 任一为空 → 不落库；AT-D-07 卡片 4 个区块顺序固定（结构断言）。

### 修正 5：阅读计划补「进度适配」（对应第 8 条）

**新增输入**：`remaining_ratio`

```
remaining_ratio = 1 - read_progress    # books 表 / knowledge_items.read_progress
remaining_chars = book.total_chars * remaining_ratio
weeks_needed = ceil(remaining_chars / (weekly_minutes * reading_speed))
```

| 规则 | 内容 |
|---|---|
| 已读完（`read_progress >= 0.95`） | **不排阅读任务，只排复习任务**（1/7/14 天三轮） |
| 读到一半 | 首周任务从"剩余部分"起排，不从第一章起 |
| reading_speed | 默认 400 字/分钟，写进 `rules_snapshot` 供用户改 |
| 与周容量联动 | 剩余量决定总周数，`weekly_minutes` 决定每周切分；两者冲突时**先保周容量**（超了就延长总周数，不压缩单周） |
| 展示 | 任务行显示"接着读 · 剩余 42%"，依据面板显示"按你读到 58% 折算，还需 3 周" |

**验收**：AT-F-06 `read_progress=0.6` 的书生成的计划，首周任务不含"从头读"且总周数 < 按 0% 排的周数；AT-F-07 `read_progress≥0.95` → 只产 `kind=review` 任务；AT-F-08 `rules_snapshot` 含 `remaining_ratio` 与 `reading_speed`。

### 修正 6：排期重估（对应第 10 条，原排期作废）

**先说实话**：A/B 细化后，验收用例累计 16 + 19 + D 7 + E 9 + F 8 ≈ 59 条，配套 3 个新模块（`grounding` / `intake` / `comprehension`）、3 张新表/字段组、5 类新卡片。**原"单人 2 天"的排期不成立**，继续按那个排就是自欺。

| 方案 | 前提 | 内容 | 能否 10-22 交付 |
|---|---|---|---|
| **甲（推荐）** | 3 人 | R1：A+B（交互主线）｜R2：D+F（归因 + 计划）｜R3：E 2 轮 + C 最小版 | 能，10-22 上午冻结 |
| **乙** | 2 人 | 两人各扛 A+B / D+F；**E 与 C 砍掉** | 能，但认知缺口这条不满足 |
| **丙** | 单人 | 只做 **B（确认流程 + 依据标注）+ D（归因七项）**；A 只修去重 bug，F 只做 `rules_snapshot` 展示不做规则引擎，E 不做 | 能，但第 6、8 条不满足 |

**我的建议是甲**。若只能单人，**必须在会上明确说"认知缺口多轮与计划进度适配本期不做"**，不能靠"降级"两个字糊过去——否则验收时会被逐条对，第 6、8 条直接判不通过。

**修正后的 P0/P1 划分**：

| 级别 | 模块 | 理由 |
|---|---|---|
| P0（必交付，缺一不可） | A 依据可溯源（含去重修复）、B 确认流程 + 依据标注 + 建议可否定、D 归因七项、E 认知缺口 2 轮 | 这四项直接对应验收清单第 1–7 条 |
| P0（做但不追求完美） | F 复习周期 + 周容量 + 兴趣 + 进度适配 | 对应第 8、9 条；规则引擎可先用固定参数 + 依据展示 |
| P1 | C 通读对比、第三方 API 评估、外部推荐接入更多源、去重唯一索引 | 不进核心演示路径 |
