## 1. 引言

### 1.1 文档目的
本文档定义「认知副驾」的产品范围与需求基线，明确**做什么**（功能需求）、**做到什么程度**（非功能需求）、**如何与外部交互**（接口需求）、**需要管理哪些数据**（数据需求），作为后续系统设计、开发、测试与验收的共同依据。

### 1.2 项目背景

在信息过载的时代，知识工作者普遍面临一个困境：收藏了大量文章、保存了海量笔记、划了无数重点，但真正需要调用时却找不到，更谈不上消化吸收。传统知识管理工具（Notion、Obsidian、Evernote 等）本质上是"存储与检索"系统——用户必须输入精准关键词，系统返回匹配结果。它们无法处理模糊输入、无法主动发起行动、无法进行逻辑推理和因果推断。

「认知副驾」（Cognitive Copilot）正是为解决这一问题而设计的 AI 智能体产品：通过持续对话与自主推理，帮助用户把"收藏的碎片"转化为"可调用的认知"，并持续修正学习方向。

### 1.3 需求来源与范围

| 项 | 说明 |
|---|---|
| 需求来源 | 《需求分析说明书》（原《认知副驾》设计原型）|
| 产品形态 | 基于大语言模型的个人知识学习智能体 |
| 本轮范围 | 五大脑力功能 + 知识接入 + 主动推送 + 计划管理 |
| 明确不做 | Web 编辑器、多人协作、内容创作社交化（首期不包含）|

> **模型依赖约束**：产品全部智能能力基于**单一外部 LLM 服务（Anthropic Claude）**提供，通过统一网关接入，不与多厂商混合编排。

## 2. 系统概述

### 2.1 目标用户

| 角色 | 角色编号 | 说明 |
|---|---|---|
| 学习者 | U1 | 主要交互对象，有收藏/笔记习惯的知识工作者或学生 |
| 知识源 | S1 | 外部系统：Notion、Obsidian、飞书、浏览器书签等 |
| 认知副驾系统 | SYS | 自身作为执行者，自主感知、推理、推送 |

**用户画像摘要**：

| 特征 | 描述 |
|---|---|
| 痛点 | 收藏即遗忘、检索靠精确关键词、学习无体系 |
| 诉求 | 主动挖掘、发现矛盾、被提醒、被纠偏、被诊断 |
| 使用频率 | 每日碎片化使用 + 每周/每月被动接收简报 |
| 技术能力 | 无需技术背景，纯自然语言交互 |

### 2.2 运行环境

| 环境 | 说明 |
|---|---|
| 服务端 | 云部署（容器化），Python/FastAPI 异步服务 |
| 模型层 | 单一 LLM 服务：Anthropic Claude API（需联网访问）|
| 外部依赖 | Claude API、知识库源 API、推送通道（App 通知 / SMTP 邮件）|
| 用户端 | Web 对话界面 / 桌面端 / 邮件（MVP 以 Web + 邮件为主）|

### 2.3 项目目标

| 编号 | 目标 | 衡量指标 |
|---|---|---|
| G1 | 将"收藏的碎片"转化为"可调用的认知" | 模糊检索一次命中率、多轮追问收敛轮数 |
| G2 | 主动发现知识矛盾并提醒 | 冲突检测覆盖新增内容比例、误报率 |
| G3 | 引导用户问"该问没问"的问题 | 认知简报每周推送的追问数 |
| G4 | 计划偏离时自主纠偏 | 行为偏离→干预→路径调整的平均时延 |
| G5 | 定位学习病根并给出方案 | 月度健康报告覆盖用户比例、诊断采纳率 |

## 3. 功能需求

功能需求按**参与角色**组织为用例（Use Case）。五大核心能力按智能体主动性从低到高（L1→L5），另含两个支撑能力（知识接入、推送与计划管理）。

### 3.1 用例总览

| 用例编号 | 用例名 | 主角色 | 能力 | 优先级 |
|---|---|---|---|---|
| UC-G-01 | 知识库接入 | 学习者 / 系统 | 支撑—知识接入 | 高 |
| UC-G-02 | 主动推送偏好管理 | 学习者 | 支撑—推送管理 | 中 |
| UC-L1-01 | 模糊意图挖掘定位 | 学习者 | L1 认知挖掘 | 高 |
| UC-L2-01 | 知识冲突主动扫描 | 系统 | L2 冲突检测 | 高 |
| UC-L2-02 | 新内容实时冲突检测 | 系统 | L2 冲突检测 | 中 |
| UC-L2-03 | 冲突反馈（忽略/采纳）| 学习者 | L2 冲突检测 | 中 |
| UC-L3-01 | 周认知简报生成 | 系统 | L3 认知助产 | 中 |
| UC-L3-02 | 深度追问生成 | 系统 | L3 认知助产 | 中 |
| UC-L4-01 | 学习计划制定与重规划 | 学习者 / 系统 | L4 路径自我修正 | 高 |
| UC-L4-02 | 行为偏离监测与干预 | 系统 | L4 路径自我修正 | 中 |
| UC-L5-01 | 月学习健康报告 | 系统 | L5 偏误诊断 | 中 |
| UC-L5-02 | 学习归因诊断 | 学习者 / 系统 | L5 偏误诊断 | 中 |

### 3.2 用例规约

> 公共用例。"学习者"为词语默认参与者（主动发起方），系统记作"系统"。

#### UC-G-01 知识库接入

| 项 | 内容 |
|---|---|
| 参与者 | 学习者（授权）、系统（执行）|
| 前置条件 | 用户已有可接入的知识源账号 |
| 主流程 | 1. 学习者授权接入某知识源（如 Notion/Obsidian/书签）；2. 系统建立连接并全量同步原文；3. 系统对新条目做向量化与主张提取；4. 系统回传同步结果给学习者 |
| 扩展 | 3a. 单条目超大→快打分块后再向量化；2a. 连接失败→提示可重试，不阻塞已有数据 |
| 后置条件 | 新增内容进入知识库，可供检索与各能力使用 |

#### UC-G-02 主动推送偏好管理

| 项 | 内容 |
|---|---|
| 参与者 | 学习者 |
| 前置条件 | 学习者已登录 |
| 主流程 | 1. 学习者选择推送频率（weekly/daily/quiet）；2. 系统保存偏好；3. 系统按偏好调度后续推送 |
| 扩展 | 3a. 学习者对同类型推送忽略≥3 次→系统自动收敛该类推荐并提示 |
| 后置条件 | 推送频率生效，且写入推送日志 |

#### UC-L1-01 模糊意图挖掘定位

| 项 | 内容 |
|---|---|
| 参与者 | 学习者（主动）、系统（对话）|
| 触发 | 输入含模糊指代/缺乏关键词/含感官描述，如"橙色封面，好像是讲拖延症的" |
| 前置条件 | 知识库已接入 |
| 主流程 | 1. 学习者输入碎片化线索；2. 系统解析产生多个候选匹配假设；3. 候选不唯一时系统向学习者发起多轮追问；4. 学习者回答缩小范围；5. 重复 2-4 直至定位；6. 系统返回精准内容并附阅读历史提醒 |
| 扩展 | 2a. 假设命中唯一→直接跳转交付；4a. 学习者无法回答→系统按最近相似度兜底返回 |
| 后置条件 | 学习者获得定位结果 |

#### UC-L2-01 知识冲突主动扫描

| 项 | 内容 |
|---|---|
| 参与者 | 系统（主动）|
| 触发 | 每周定时 |
| 主流程 | 1. 系统扫描新增知识条目；2. 提取各自核心主张；3. 进行语义比对与逻辑分析；4. 识别矛盾/互补/断层关系并过滤误报；5. 形成冲突候选（含置信度）；6. 推送冲突提醒与对比分析 |
| 扩展 | 4a. 置信度低于阈值→不入库不推送（误报抑制）|
| 后置条件 | 冲突候选写入，支持学习者反馈（见 UC-L2-03）|

#### UC-L2-02 新内容实时冲突检测

| 项 | 内容 |
|---|---|
| 参与者 | 系统 |
| 触发 | 学习者收藏新文章 |
| 主流程 | 1. 新条目入库；2-5. 同 UC-L2-01；6. 实时推送冲突提醒 |
| 后置条件 | 冲突提醒已送达 |

#### UC-L2-03 冲突反馈（忽略/采纳）

| 项 | 内容 |
|---|---|
| 参与者 | 学习者 |
| 前置条件 | 存在冲突提醒 |
| 主流程 | 1. 学习者查看冲突；2. 选择"忽略"或"采纳"；3. 系统记录反馈 |
| 扩展 | 2a. 忽略同类型≥3 次→系统收敛该类冲突推荐 |
| 后置条件 | 反馈写入，用于收敛与信任度量 |

#### UC-L3-01 周认知简报生成

| 项 | 内容 |
|---|---|
| 参与者 | 系统 |
| 触发 | 每周定时 |
| 主流程 | 1. 系统分析知识库主题分布与认知深度；2. 识别"大量存在/完全缺失"模式；3. 生成 2-3 个启发式深度追问；4. 汇总本周冲突同比；5. 形成认知简报推送 |
| 后置条件 | 简报已推送并记录 |

#### UC-L3-02 深度追问生成

| 项 | 内容 |
|---|---|
| 参与者 | 系统 |
| 触发 | 学习者完成问答或收藏新内容后 |
| 主流程 | 1. 系统获取上下文；2. 基于缺失项生成 1 个与当前话题衔接的深度问题；3. 附数据依据推送；4. 学习者可选择继续探讨 |
| 后置条件 | 追问已推送，可承接新一轮对话 |

#### UC-L4-01 学习计划制定与重规划

| 项 | 内容 |
|---|---|
| 参与者 | 学习者（目标输入）、系统（计划生成）|
| 前置条件 | 学习者设定学习目标（可包含目标期限与优先级）|
| 主流程 | 1. 学习者设定学习目标；2. 系统拆解为周维度任务计划；3. 系统回传计划供确认；4. 学习者确认或修改；5. 系统写入计划 |
| 扩展 | 4a. 需要调整→进入重规划（同 UC-L4-02 步骤 3-6）|
| 后置条件 | 计划生效，进入行为监测 |

#### UC-L4-02 行为偏离监测与干预

| 项 | 内容 |
|---|---|
| 参与者 | 系统（主动）、学习者（确认）|
| 触发 | 连续 N 天（默认 3）未执行计划 / 行为模式显著变化 / 学习者主动请求 |
| 主流程 | 1. 系统聚合学习行为（阅读/收藏/问答）；2. 分析偏离原因；3. 生成路径调整建议；4. 发起干预对话询问是否同意；5. 学习者同意→系统重拆计划并确认新路径（含预期收益）；6. 学习者拒绝→保持原计划并记录偏好 |
| 后置条件 | 路径已更新或保持原状，行为监测继续 |

#### UC-L5-01 月学习健康报告

| 项 | 内容 |
|---|---|
| 参与者 | 系统（主动）|
| 触发 | 每月定时 |
| 主流程 | 1. 系统批量分析学习行为数据；2. 多因素归因；3. 形成诊断报告（含置信度与简要推理链）；4. 推送健康报告；5. 询问是否采纳诊断结论 |
| 后置条件 | 报告已推送；采纳后解决方案拆为任务写入计划（见 UC-L4-01）|

#### UC-L5-02 学习归因诊断

| 项 | 内容 |
|---|---|
| 参与者 | 学习者（主动）、系统（回答）|
| 触发 | 学习者主动询问"我为什么学不好/总拖延"等 |
| 主流程 | 1. 学习者提出问题；2. 系统基于行为数据链式归因；3. 返回诊断 + 可执行方案；4. 学习者可要求采纳/写入计划 |
| 后置条件 | 诊断已交付，可选进入计划更新闭环 |

## 4. 非功能需求

### 4.1 性能需求

| 编号 | 指标 | 目标 |
|---|---|---|
| 性能-1 | 对话首字响应 | ≤ 3s（普通任务）；深度推理显示"思考中"占位 |
| 性能-2 | 语义检索 P95 | ≤ 500ms |
| 性能-3 | 批量扫描吞吐 | 异步执行，不阻塞在线请求 |
| 性能-4 | 周/月简报生成 | 后台任务完成，用户无感知等待 |

### 4.2 易用性需求

| 编号 | 指标 | 目标 |
|---|---|---|
| 易用-1 | 交互方式 | 纯自然语言对话，零学习成本 |
| 易用-2 | 知识接入 | 用户一次授权即可，无需额外操作 |
| 易用-3 | 打扰控制 | 推送可设频率与免打扰，避免过度打扰 |

### 4.3 可靠性需求

| 编号 | 指标 | 目标 |
|---|---|---|
| 可靠-1 | 模型服务容错 | Claude API 异常自动重试（重试 2 次），不因单次失败中断 |
| 可靠-2 | 状态一致性 | 关键写操作走事务，计划/诊断采用乐观锁防覆盖 |
| 可靠-3 | 任务可靠性 | 定时任务具备失败重试与死信告警；支持断点续跑 |
| 可靠-4 | 依赖降级 | 向量库不可用时回退关键词检索，功能降级不中断 |

### 4.4 安全与合规需求

| 编号 | 指标 | 目标 |
|---|---|---|
| 安全-1 | 传输 | 全链路 TLS 加密 |
| 安全-2 | 存储 | 用户知识内容 AES-256 落库加密，最小化日志 |
| 安全-3 | 隔离 | 多租户 key/额度隔离，防越权 |
| 安全-4 | 数据使用 | 不做超越授权范围的数据使用；删除支持软删+合规可擦除 |
| 安全-5 | 输出校验 | 模型输出经敏感词/内容校验过滤 |

### 4.5 可扩展性与可维护性需求

| 编号 | 指标 | 目标 |
|---|---|---|
| 扩展-1 | 知识库源扩展 | 连接器插件化，新增来源不影响核心流程 |
| 扩展-2 | 能力扩展 | 五大能力独立模块，可单独增删/灰度 |
| 维护-1 | 可观测性 | 统一 request_id 全链路日志，成本与调用埋点齐全 |
| 维护-2 | 可配置性 | 规则/提示词/推送策略配置化热更新 |

## 5. 接口需求

### 5.1 外部接口总览

| 接口 | 方向 | 协议 | 说明 |
|---|---|---|---|
| 用户对话接口 | 用户 ↔ 系统 | HTTPS/REST | 自然语言对话入口 |
| 知识库源接口 | 系统 → 知识源 | 官方 API/SDK | Notion/Obsidian/飞书/书签接入 |
| 推送通道接口 | 系统 → 推送通道 | SMTP / App 推送 | 周/月/日简报与提醒 |
| 模型服务接口 | 系统 → Claude API | Anthropic API | 全部智能能力的单一模型依赖 |

### 5.2 用户侧接口（功能框架）

| 能力 | 接口需求 |
|---|---|
| 对话 | 支持多轮自然语言交互，可跟随 Tool 调用完成动作 |
| 知识管理 | 新增/查询/导入知识条目 |
| 目标与计划 | 设定目标、查看/调整计划 |
| 诊断与报告 | 查询最新诊断、健康报告 |
| 偏好设置 | 更新推送频率与其他偏好 |
| 成本查询 | 查询模型费用明细 |

> 具体 REST 路径与参数在系统设计阶段细化，此处仅约束功能范围与语义。

### 5.3 模型服务接口约束

| 约束项 | 说明 |
|---|---|
| 单一依赖 | 全部模型调用收敛到统一网关，业务层不感知实现细节 |
| 能力要求 | 需支持：工具调用（Tool Calls）、思考模式（Thinking）、长上下文、Prompt 缓存 |
| 可替换性 | 通过抽象接口封装，保留未来替换/新增服务商的能力（虽本期仅 Claude）|
| 失败处理 | 统一重试、限流、熔断与成本埋点 |

## 6. 数据需求

### 6.1 核心数据实体

| 实体 | 用途 | 关键属性 |
|---|---|---|
| User（用户）| 账号、偏好 | 昵称、推送频率、加密 key |
| KnowledgeItem（知识条目）| 知识库基本单位 | 标题、正文、来源、标签、阅读进度、核心主张 |
| LearningGoal（学习目标）| 目标管理 | 描述、期限、优先级、是否达成 |
| LearningPlan（学习计划）| 计划管理 | 目标关联、结构化计划内容 |
| PlanTask（计划任务）| 任务拆解 | 周次、主题、状态、关联条目 |
| CognitiveDiagnosis（诊断报告）| 偏误诊断输出 | 行为模式、归因、置信度、推理链、状态 |
| Conflict（观点冲突）| 冲突检测产物 | 条目 A/B、冲突类型、细节、建议、用户状态 |
| Conversation（会话）| 对话状态 | 状态机状态、上下文 |
| PushLog（推送日志）| 推送追溯与去重 | 类型、内容 hash、渠道、用户反馈 |

### 6.2 数据存储策略

| 存储 | 承载数据 | 说明 |
|---|---|---|
| 关系库（PostgreSQL）| 用户/目标/计划/诊断/冲突/推送日志 | 事务强一致 |
| 向量库（pgvector / Milvus）| 知识条目 Embedding | 语义检索 |
| 缓存（Redis）| 会话状态/限流/短期记忆 | 低延迟 |
| 对象存储 | 原文附件/长文快照 | 大文件 |

### 6.3 数据安全与生命周期

| 项 | 需求 |
|---|---|
| 敏感分级 | 用户知识内容属敏感个人数据，加密存储、最小化收集 |
| 软删除 | 全表软删（is_deleted + deleted_at），避免误删不可恢复 |
| 生命周期 | 归档（不参与检索，可恢复）→ 保留期到期后物理清除（合规可擦除）|
| 追溯 | 推送与模型调用留痕，支持审计与成本归因 |
